# لاب ٤ — شرح التنفيذ والقرارات خطوة بخطوة

هذا اللاب يختبر سؤالًا عمليًا: هل تجهيز النص بطريقة تناسب العربية يحسّن النموذج؟ نحتاج تنفيذًا صحيحًا وتجربة عادلة؛ نجاح الكود لا يعني تلقائيًا تحسن النتيجة.

## ١. قرأنا المتطلبات والاختبارات

ملفات العمل هي `src/bayan/preprocessing/arabic.py`، و`scripts/dialect_audit.py`، و`scripts/arabic_bakeoff.py`. أضفنا `scripts/ner_segmentation_eval.py` لتجربة NER، و`scripts/setup_lab4.py` لتجهيز بيانات المحلل الصرفي.

أبقينا الاختبارات والبيانات الأصلية كما هي. ملف الاختبارات يحتوي 30 صفًا، لكنه يكرر 10 أمثلة مختلفة ثلاث مرات؛ لذلك أضفنا اختبارات للحالات التي لا تغطيها هذه الأمثلة.

## ٢. نفذنا ملفّي التطبيع

التطبيع يعني توحيد بعض أشكال الكتابة قبل إدخالها للنموذج. الملف `bayan_ar_v1` ينفّذ القواعد التي تطلبها الأمثلة الأصلية:

| قبل | بعد | السبب |
|---|---|---|
| أ، إ، آ، ٱ | ا | توحيد أشكال الألف |
| ؤ | و | توحيد الحرف الحامل للهمزة وفق ملف المقرر |
| ئ، ى | ي | توحيد أشكال الياء والألف المقصورة |
| ة | ه | قاعدة مطلوبة في اختبارات المقرر |
| مـدرسة | مدرسه | إزالة التطويل ثم تطبيق التحويلات |
| خِدْمَة | خدمه | إزالة التشكيل عند تفعيل الخيار |

نطبّق NFC، ونوحّد الفراغات. لا نحذف الرموز التعبيرية أو نغيّر حالة الحروف الإنجليزية. ولا نستدعي تقليل تكرار الحروف من لاب ١ هنا: المثال `أإآا` يجب أن يصبح `اااا`، وليس `اا`.

الملف الثاني `camelbert_v1` هو اسم اخترناه للمشروع؛ ملفات المقرر لم تحدد اسمًا ثانيًا أو أمثلة له. يزيل التشكيل والتطويل وينظّم الفراغات، لكنه يحافظ على اختلاف الألف والتاء المربوطة. يتبع وصف تجهيز النص في [بطاقة CAMeLBERT الرسمية](https://huggingface.co/CAMeL-Lab/bert-base-arabic-camelbert-mix#preprocessing)، ولا ندّعي أنه اسم ملف رسمي من الجامعة.

```python
from bayan.preprocessing.arabic import normalize_arabic, BAYAN_AR_V1, CAMELBERT_V1

normalize_arabic("إضاءةُ مـدرسة", BAYAN_AR_V1)
# 'اضاءه مدرسه'
normalize_arabic("إضاءةُ مـدرسة", CAMELBERT_V1)
# 'إضاءة مدرسة'
```

**لماذا لا نستخدم التحويل الأقوى دائمًا؟** لأنه يفقد معلومات: «على» و«علي» يصبحان متطابقين. تجهيز النص يجب أن يناسب ما تعلّمه النموذج، وليس مجرد جعل النص أقصر أو أكثر تجانسًا.

## ٣. فصلنا نص العرض عن نص النموذج

الدالة `prepare_arabic_text` تُرجع `display_text` و`model_text`، مع اسم الملف ورقم إصداره. نُخفي الهاتف والهوية قبل إنشاء النسختين، ثم نطبّع نسخة النموذج فقط.

```python
from bayan.preprocessing.arabic import prepare_arabic_text, BAYAN_AR_V1

prepare_arabic_text("إضاءةُ مـدرسة 0551234567", BAYAN_AR_V1)
# display_text: 'إضاءةُ مـدرسة <PHONE>'
# model_text:   'اضاءه مدرسه <PHONE>'
```

هذا يحافظ على كتابة النص للمستخدم دون عرض بيانات شخصية. ولا نستبدل نصوص QA بهذه النسخة؛ تغيير طول النص هناك قد يغيّر مواضع الإجابات.

## ٤. دققنا توزيع اللهجات

نشغّل:

```bash
python scripts/dialect_audit.py
```

السكربت يعدّ قيم `dialect_region` في الصفوف العربية فقط. هو تدقيق للتسميات المرفقة، وليس نموذجًا يتعرف على اللهجة من النص.

| القسم | خليجي | فصحى |
|---|---:|---:|
| التدريب | 4800 | 1200 |
| التحقق | 0 | 1200 |
| الاختبار النهائي | 0 | 0 |
| إجمالي العربية | 4800 | 2400 |

العربية 7200 صف من أصل 12000. الخليجي يمثل 66.67% من العربية، والفصحى 33.33%. **جميع أمثلة الخليج في التدريب**؛ وبالتالي لا يمكن إثبات جودة التعميم على الخليجي من أقسام التقييم الحالية. الصفوف الإنجليزية لا تدخل في هذه النسب.

هذا أقوى من ملاحظة «نحتاج تقييم اللهجات»: التقسيم الحالي نفسه يمنع قياس التحسن الخليجي المطلوب. لا نعالج المشكلة بنقل أمثلة تدريب إلى التحقق بعد أن تدرب عليها نموذج لاب ٣.

## ٥. جهّزنا CAMeL Tools واخترنا D3

الحزمة البرمجية كانت مثبتة، لكن بيانات التحليل الصرفي لم تكن موجودة. الأمر التالي يثبت نموذج MLE وقاعدة MSA المطلوبة فقط، داخل `artifacts/camel_tools`:

```bash
python scripts/setup_lab4.py
```

نستخدم `MLEDisambiguator` بقاعدة `calima-msa-r13` مع مخطط `d3tok`. وفق [توثيق CAMeL الرسمي](https://camel-tools.readthedocs.io/en/latest/api/tokenizers/morphological.html)، D3 يفصل لواصق مثل حروف العطف والجر وأداة التعريف.

```python
from bayan.preprocessing.arabic import segment

segment("وبالرياض")
# ['و+', 'ب+', 'ال+', 'رياض']

segment("انقطعت الكهرباء وبالرياض تأخرت الصيانة")
# ['انقطعت', 'ال+', 'كهرباء', 'و+', 'ب+', 'ال+', 'رياض',
#  'تأخرت', 'ال+', 'صيانة']
```

علامة `+` تبيّن الجزء الذي كان متصلًا بالكلمة؛ ليست جزءًا جديدًا من الجملة الأصلية. استخدمنا محللًا صرفيًا بدل قطع أول حرف من كل كلمة: ليست كل كلمة تبدأ بحرف الواو مسبوقة بحرف عطف.

موارد MSA لا تضمن تحليلًا صحيحًا لكل لهجات الخليج. نسجّل ذلك كحد للتجربة، ولا نقدّم هذا المحلل على أنه مختبر على اللهجة الخليجية.

## ٦. حافظنا على محاذاة NER

في لاب ٣ لكل كلمة وسم مثل `B-LOCATION`. بعد التقسيم قد تصبح الكلمة أربعة أجزاء. المقارنة المباشرة بين أربع تنبؤات وتسمية واحدة ستكون خاطئة.

تُرجع `ner_segmented_view` الأجزاء وموضع الجزء الأساسي لكل كلمة أصلية. في «وبالرياض» يكون الموضع 3، أي «رياض». نأخذ أول subword لذلك الجزء ثم نعيد التنبؤ إلى موضع الكلمة الأصلية. اختيار الموضع يعتمد على التحليل الصرفي فقط، لا على الإجابة الصحيحة.

أضفنا كذلك `--segmentation camel_d3` إلى `scripts/train_ner.py`. عند تدريب تجربة منفصلة بهذه الطريقة، نضع التسمية على الجزء الأساسي، و`-100` على بقية اللواصق واستمرارات subwords. نفس التحويل يُستخدم في التدريب والتحقق والتقييم. إعداد التجزئة يُحفظ مع النموذج ويُستعاد عند التقييم.

```bash
# مثال لتجربة جديدة فقط؛ لم ندرّب هذا النموذج الإضافي في هذا اللاب.
python scripts/train_ner.py --segmentation camel_d3 --output-dir artifacts/ner_d3
```

لم نستبدل نموذج لاب ٣ بهذه التجربة أو نعد تشغيل اختباره النهائي. ملف `bayan_ner_segmented.conll` الأصلي بقي محفوظًا؛ التجربة تولّد الأجزاء بالمحلل الفعلي مع خريطة للكلمات الأصلية.

## ٧. قسنا أثر التقسيم على النموذج الموجود

```bash
python scripts/ner_segmentation_eval.py
```

ثبّتنا طريقة المقارنة قبل الاستدلال في `ner_segmentation_protocol.json`. استخدمنا 935 مثالًا من **التحقق**، ونفس أوزان NER المحفوظة. استعدنا تنبؤات المسار الأصلي المحفوظة، ثم حسبنا تنبؤات المدخلات المقسمة فقط. لا تدريب جديد ولا استخدام للاختبار النهائي في هذه التجربة.

| المقياس | النص الأصلي | بعد D3 |
|---|---:|---:|
| LOCATION recall | 100% | 76.36% |
| LOCATION F1 | 100% | 86.60% |
| إجمالي entity micro-F1 | 100% | 94.09% |

`Recall = المواقع المستخرجة صحيحًا ÷ جميع المواقع الصحيحة`. الفرق **−23.64 نقطة**. هدف +4 نقاط لم يتحقق؛ وهو غير ممكن فوق خط أساس 100% على هذه العينة.

القرار: **نحتفظ بالمدخلات الأصلية للنموذج الحالي**. التفسير المحتمل هو اختلاف مدخلات D3 عن الكلمات التي رأى النموذج أثناء التدريب. التجربة لا تثبت أن التقسيم يضر جميع نماذج العربية؛ تثبت أنه لم يساعد هذا النموذج، بهذا الإعداد، على عينة التحقق الحالية.

## ٨. المقارنة الاختيارية بين Mix وDA

```bash
python scripts/arabic_bakeoff.py --train
```

ندرب CAMeLBERT-Mix وCAMeLBERT-DA على الـ6000 صف عربي من التدريب، ونقيّمهما على الـ1200 صف عربي من التحقق. نستخدم `camelbert_v1` في القسمين، ونثبت seed=42، وحقبتين، وlearning rate=2e-5، وbatch size=16 مع accumulation=2، وطولًا أقصى 64. رأس التصنيف جديد ويتعلم أثناء fine-tuning.

نختار أفضل حقبة باستخدام macro-F1 للتحقق. نسجل نسخة كل checkpoint وإعدادات التجربة في `arabic_bakeoff_protocol.json`. المقارنة مع XLM-R تعيد استخدام تنبؤاته المحفوظة على نفس الصفوف؛ لا نعيد اختبار النموذج النهائي.

عمود Gulf سيكون `null` لأن عدد أمثلته في التحقق صفر. لا نحوله إلى صفر أداء أو نستنتج منه تفوق DA. بعد التشغيل تعادل Mix وDA مع XLM-R: accuracy=1.00 وmacro-F1=0.50 على الفصحى. السقف 0.50 لأن أربع فئات فقط من ثمانٍ موجودة في التحقق العربي. استغرق تشغيل Mix نحو 174.33 ثانية وDA نحو 173.85 ثانية على MPS. احتفظنا بـXLM-R؛ لا يوجد دليل تفوق خليجي. التفاصيل في `BENCHMARKS.md` و`DECISIONS.md#arabic-model`.

واجه حفظ BERT على MPS أوزانًا غير متجاورة في الذاكرة؛ `ContiguousTrainer` ينقل نسخة الأوزان إلى CPU بتخطيط متجاور وقت الحفظ، دون تغيير قيمها أو خوارزمية التدريب. أضفنا اختبارًا يحفظ وزنًا بهذا الشكل ويعيد تحميله ويقارن القيم.
